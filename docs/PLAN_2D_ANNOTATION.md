# Plan — a 2D annotation tool

Written 2026-09-04. Scope: 2D only. Nothing here touches the 3D pipeline.

The goal is to close the loop **train -> annotate -> retrain** for the 2D
segmenter. Today the first and third steps work and the middle one does not
exist.

---

## Why this is needed

`/annotate` has a "2D slices" tab, but it is a text panel that says *"The 2D
model needs no drawing"* — see
[annotate/page.tsx:144](../client/nextjs/src/app/(dashboard)/annotate/page.tsx#L144).
That was true when the only 2D model was the yes/no classifier, whose label is
the case class and needs no drawing at all.

It stopped being true when the 2D segmenter arrived. Every painting path in
[Viewer.tsx](../client/nextjs/src/app/(dashboard)/annotate/Viewer.tsx) works on
a 3D volume: it loads a `.nii.gz`, paints into a flat `i,j,k` label array, and
saves a `.seg.nrrd`. **Nothing in the app can open a PNG and let you draw on
it**, and the 2D dataset is PNGs.

So: `data/annotations/` is empty, `data/seg2d/` cannot be built, and
`train_2d_seg.py` has nothing to train on.

---

## The contract — build to this and the trainer needs no changes

[train_2d_seg.py:175](../ml/scripts/train_2d_seg.py#L175) already reads a fixed
layout, and it is the only thing that matters:

```
data/seg2d/
  index.csv          case_id, image, mask, has_lesion
  images/<name>.png  grayscale slice
  masks/<name>.png   uint8, 0=background 1=bone_marrow 2=bme 3=uncertain
```

It groups folds by `case_id` and hard-fails if folds exceed case count. **Write
this layout and the existing trainer works unmodified.** Do not invent a second
format and do not edit the trainer to accommodate one.

## Design

### The rule this inherits from the 3D side

CLAUDE.md §3: *"`data/annotations/*.seg.nrrd` is the only file a human edits.
Every `.nii.gz` labelmap is generated by script and is disposable."*

Keep that shape. One human-edited artifact, everything else regenerated:

```
data/annotations2d/<case_id>/<image_stem>.mask.png   <- the ONLY hand-edited file
data/seg2d/                                          <- generated, disposable
```

A build script assembles `data/seg2d/` from the masks plus the source images.
Delete `data/seg2d/` at any time and rebuild. This matters more than it looks:
it is what lets you change the training format later without re-annotating.

### Label values

Same mapping as 3D, **keyed by name, never by order**:

| value | name | why |
|---|---|---|
| 1 | `bone_marrow` | bounds the lesion; the dual-channel U-Net predicts it |
| 2 | `bme` | the lesion |
| 3 | `uncertain` | excluded from loss, not treated as background |

Paint bone marrow even when it feels redundant. A lesion-only model has no idea
where bone ends and reports edema in soft tissue.

Modify `annotate/page.tsx` — replace the placeholder in the `2d` tab with
`<Painter2D/>`. Everything else stays.

### Painter2D — what it actually needs

Two stacked `<canvas>` elements at the image's natural size: the scan on the
bottom, the label layer on top at ~40% alpha. Paint into an `Uint8Array` of
`w*h`, not into canvas pixels — the array is the truth, the canvas is a view of
it. That is the same split
[Viewer.tsx:133](../client/nextjs/src/app/(dashboard)/annotate/Viewer.tsx#L133)
uses, and it is why undo there is cheap.

Minimum controls: brush size, the three labels, eraser, undo, save. Zoom and
pan can wait; at 500-900 px these images fit on screen unscaled.

Save posts the `Uint8Array` as a PNG (palette or grayscale, values 0-3 — **not**
an RGB screenshot; the whole point is to avoid re-deriving labels from colour).

## Build order

1. **`make_seg2d_from_masks.py` first, with a hand-made mask.** Paint one mask
   in any image editor, drop it in, run the script, run `train_2d_seg.py` for
   one epoch. This proves the contract end to end before any UI exists. If the
   trainer chokes, you have found it while one file is wrong, not fifty.
2. `api/cases2d` + `api/annotation2d` — verify with `curl` alone.
3. `Painter2D.tsx`, wired into the existing tab.
4. Annotate 5 cases, run the pipeline, confirm a number comes out.
5. Then annotate in bulk.

Do not build the UI first. It is the most enjoyable part and the least likely
to be where the problem is.

## Decide before writing code

- **Grayscale or RGB source?** `build_2d.py` currently writes RGB. The trainer
  loads `Image.open(...)` and divides by 255 — feeding it RGB where it expects
  one channel is a shape mismatch waiting to happen. Settle this first.
- **Sizes are not uniform** — 320x320 up to 867x731. The trainer resizes, but
  the mask must be resized with NEAREST or the labels blur into invented
  values. `make_2d_seg.py:107` already has this right; copy that line.
- **Who annotated what.** The 3D side has `data/annotation_log.json` and a `by`
  query param. With four people, add the same here from the start.

---

## Risks, in the order they will bite

**Annotating the wrong thing.** BME on fat-suppressed PD is bright and fuzzy
with no crisp edge. Two annotators will disagree by a lot. Read
[ANNOTATION_SOP.md](ANNOTATION_SOP.md) before the first stroke, and have the
first three cases checked by the guide before doing fifty.

**18 BME patients.** That is the entire positive pool. At 5 folds that is 3-4
per validation fold, so fold-to-fold spread will likely exceed any effect being
measured. Report mean +/- std across folds and say the n out loud. Do not quote
a best fold.

**Class imbalance, 3.8:1 toward non-BME.** Use class weighting and report
per-class recall; overall accuracy will look fine for the wrong reason.

**PHI.** `BME/2d` filenames were patient names until they were renamed on
2026-09-04; the map is at `Annotated/deid_map_2d.csv`, outside the repo. Any new
API must return pseudonymous ids only — copy the `SHOW_SOURCE_NAMES` guard in
[api/cases/route.ts:19](../client/nextjs/src/app/api/cases/route.ts#L19)
rather than inventing a new rule.

## Done means

- Paint a mask in the browser, save, reload the page, mask is still there.
- `make_seg2d_from_masks.py` builds `data/seg2d/` from what was painted.
- `train_2d_seg.py` runs on it unmodified and reports Dice per fold.
- Deleting `data/seg2d/` and rebuilding gives the same result.
- No patient name appears in any API response, filename, or log line.
